## 后端行为与配置

| 运行场景 | 修复后的默认时间 | 默认步骤 | 行为 |
| --- | ---: | ---: | --- |
| 自由搜集构建 `research` | `researchTimeoutMs=900000` | `researchMaxSteps=48` | 保留自由研究入口，不依赖自动构建状态；达到预算后停止并报告原因 |
| 自动构建采集 `research` | `researchTimeoutMs=900000` | `researchMaxSteps=48` | 已保存且勾选的可用来源达到目标时，在下一模型步骤前停止采集 |
| 资料问答 `sources` | `assistantTimeoutMs=180000` | `assistantMaxSteps=24` | 保持原有问答预算与来源模式限制 |
| 自动构建导读 | 独立 `assistantTimeoutMs=180000` | 独立模型请求 | 采集结束后重新计时，不继承采集预算已取消的信号 |
| Studio 产物 | 每个任务 `assistantTimeoutMs=180000` | 独立模型请求 | 保持可取消后台生成；使用动态输入和输出预算 |

自动构建达到来源目标后返回原生预步拒绝决策，不再额外请求模型整理采集结果，也不先执行下游压缩。来源目标按实际保存且仍勾选的来源计算；来源记录数不代表资料独立性、完整性或内容质量。

自动采集达到时间、步骤或模型限制时，只要有已保存的可用证据，就尝试用独立预算生成部分导读；整体状态仍为部分完成，保留原失败原因，不能因导读成功而掩盖采集失败。没有来源时不调用模型生成导读。用户主动取消、插件关闭或投影故障优先停止，不能因已有来源而擅自开始新一轮生成；已提交资料继续保留。自由搜集构建不自动套用部分导读流程。

### 降低工具与重复资料开销

- `notebook_source` 默认返回 6000 个 UTF-16 字符，单页上限 12000；支持 `offset`、`limit`，返回 `bodyLength`、`nextOffset` 和 `hasMore`。继续读取使用返回的 `nextOffset`，避免自行推算字符边界。资料库与来源详情保留已保存全文。
- 搜集构建阶段不再每步重复注入最多 16000 字符的来源片段；自动研究要求只作为本轮用户消息发送一次。
- 原生工具结果先经过真实正文入库观察，再在下一步骤前裁剪长工具输出。来源正文不从裁剪后的聊天表面反向恢复。
- 优先复用宿主原生裁剪和自动压缩，不自行删历史，不暗改被冻结的请求消息，也不重复挂载压缩引擎。缺少裁剪能力时不操作；实际服务解析或日志写入失败保持可见。

本机 DSH `0.2.2-rc.3` 的 preset 服务位于隔离 group。先查询 `agent.ctx.get('toolResultPruner')`；缺失时通过 `agentPresets.serviceFor(agent, 'toolResultPruner')` 取得，然后调用 `pruneSession(agent.session)`。`serviceFor` 已从实际安装的 `app.asar` 核对，并非仅依据其他版本源码推测。

原生默认阈值为 8192 字符，保留头部 4096、尾部 1024 和裁剪标记；字符计量使用 Unicode code point。裁剪追加 `compaction/prune` 与带 `surfaceOp: replace` 的 `tool/result`，原始 journal 不删除。SQLite 的工具消息投影可能更新为裁剪版，不能把原始日志保留等同于每种界面投影都保留全文。

### 独立导读与 Studio 的模型窗口预算

生成前通过宿主 `llm.resolveModelInfo` 获取实际路由的窗口与默认输出值。`assistantMaxTokens` 默认 8192；选择它与路由默认输出的较小值是本插件策略，路由默认值不是模型硬上限。已知窗口时，输出最多占四分之一，并另留最多 1024 tokens 的消息保护空间；小窗口按比例留余量。

输入按完整 prompt 的 UTF-8 字节数作保守 token 上界，并再留消息余量。只缩短证据片段，按 source ID 尽量均衡分配；多片段来源不能挤占其他来源的全部空间。最终 prompt、来源元数据和引用校验使用同一组适配后的片段，用户要求与笔记本说明保持完整。固定内容过大或无法保留每个来源的必要证据时，在调用模型前明确报错并给出缩短要求、减少来源或换模型的处理方向。

宿主没有窗口信息时，保留既有 `maxInjectChars=16000` 的候选片段预算，不猜测模型容量。模型元数据读取失败、取消或输出达到预算仍会明确报告，不能把残缺产物保存为完成。保守字节预算可能比真实 tokenizer 更早缩短片段，这是保护独立请求的取舍。

### 真实裁剪接入修复与资料问答

第一轮构建后，原生日志尚无裁剪事件，旧的 seq 30 长工具结果仍为 28,633 字符。真实探测确认 `directPruner=false`、`presetPruner=true`，因此补上公开 registry 解析；这是本轮真实验收发现并修复的问题。

修复后在同一工作台运行 `sources` 模式的资料问答，任务 `ae966919-bcd4-44ca-9fd8-439f35971b13` 完成，5 步、12,049 ms。原生界面已看到带真实来源引用的回答，并正确区分已保存资料的规则说明、书目条目与题名片段，说明未覆盖的细则。

完整解码原生 Session 的连续 zstd 帧后，确认：

- `compaction/prune` seq 176 指向旧 seq 30，后续替换 `tool/result` 为 seq 177。
- 原结果 28,633 字符，替换结果 5,159 字符，减少 23,474 字符；原 seq 30 仍完整保留在日志中。
- 真实测量从问答前 `totalTokens=45803 / surfaceTokens=44984` 到结束后 `25420 / 23137`。这一变化同时包含新问答的请求结构与取材变化，不能全部归因于单次裁剪，亦不是通用性能基准。
